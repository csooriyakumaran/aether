  ## Roadmap

### Features (new capability)

  - [x] `arena_read_file` helper — the README's own "Temporary File Processing" use case hand-rolls fopen/fseek/ftell/fread into an arena; that's common enough to be a real function instead of copy-pasted boilerplate each time.
  - [x] str8 operations — equality/comparison, slicing, trim, prefix test, and split-once done (`str8_eq`/`str8_cmp`/`str8_slice`/`str8_trim`/`str8_has_prefix`/`str8_cut`, plus `view_from_c_str`); find and split also landed: find is an out-param + `b8` return (`str8_find`/`str8_find_last`/`str8_find_char`, matching `os_file_size`'s convention, as leaned); split shipped as an allocating `Str8List str8_split(...)`, not the non-allocating iterator originally leaned toward — simpler to ship, and a non-allocating variant remains a possible future addition if a parse loop needs it. All tested in `tests/test_strings.c`.
  - [ ] POSIX backend — full itemized breakdown (arena `os_mem_*` shims, ring buffer via `memfd_create`/`mmap`, thread/atomics/timer POSIX paths, staging order) now lives in `docs/posix-port.md`; this line is just the roadmap pointer, not the checklist.
  - [x] add `os_file_map` / `os_file_unmap` using `CreateFileMapping`/`MapViewOfFile` for direct mem-mapping of OS files. (for WIN32 for now)
  - [x] ring / circular buffers — virtually-mirrored ("magic") ring buffer on Win10 1803+. `VirtualAlloc2`/`MapViewOfFile3`/`UnmapViewOfFile2` are resolved at runtime via `GetProcAddress` from `kernelbase.dll`, so there is no extra link dependency and the binary still loads on older Windows (alloc just returns `false`). Tested across mirror/seam/stream/counter-wrap in `tests/test_ring.c`.
  - [ ] add `os_file_open_ex` (for fine control) — `os_file_open_for_write` shipped in 0.0.12; the `todo(chris)` comment near it is the only remaining trace of this item.

### Quality of life (easier to use, same capability)
  - [x] Scratch/temp-arena helper (`ArenaTemp` + `arena_temp_begin`/`arena_temp_end`) — wraps the manual `u64 mark = arena.pos; ... arena_pop_to(&arena, mark);` pattern you already do by hand everywhere.
  - [x] `CHANGELOG.md` — now that real tags exist, worth more than `gh release --generate-notes` alone once there's more than one release to compare across.
  - [x] Release automation (`scripts/release.ps1`) — mechanical Phase-B driver: pre-flight guards (on `master`, clean tree, tag absent locally+on `origin`, `gh` authenticated, target `## [X.Y.Z]` changelog section present), `ctest` gate, then drop `-dev` → commit `release: vX.Y.Z` → annotated tag → push → `cmake --install` + `Compress-Archive` → `gh release create` with notes sliced from the curated `CHANGELOG.md` section → re-bump to the next `-dev`. `-DryRun` runs the read-only pre-flight for real but narrates every mutating step. Content edits (CHANGELOG/README/TODO) stay **manual by design** — the script *verifies* the changelog section exists rather than generating prose.
  - [ ] GitHub Actions CI — build + `ctest` on push/PR. Cheap now that there's a real test suite; catches regressions before they reach a tag. Distinct from the release script above: that gates *releases*, this gates *every push/PR*. Could later share the build+test step (the release script's gate is the same `cmake`/`ctest` invocation a CI job would run).

  ### Hardening / process
  - [ ] Decide an error-handling convention before adding more I/O-shaped APIs. Arenas now hard-abort on OOM — a fine, deliberate choice for memory. `arena_read_file` and friends will hit a *different* failure shape (missing file, permission denied) that isn't obviously "abort-worthy" the same way. Decide the convention once, not per-function.
  - [x] **Standard C11 / C++11 conformance.** Compound-literal returns converted to named temporaries with positional init; `STR` routed through `AETHER_LITERAL(T)` (`(T)` in C, `T` in C++). Header no longer relies on compiler extensions. Gated by pedantic compile probes `tests/verify_c11.c` (`-std=c11 -pedantic-errors` / `/permissive-`) and `tests/verify_cxx11.cpp` (`-std=c++11 -pedantic-errors` / `/permissive-`), wired into ctest. NB: floor is C11, not C99 — there is no conformant C99 `alignof` (`_Alignof` is C11; the `offsetof(struct{...},m)` idiom is a C23 extension that clang rejects under `-pedantic-errors`), so `ARENA_ALIGN` keeps `_Alignof`/`alignof`. Probes are header-only (the `AETHER_IMPLEMENTATION` body pulls in `<windows.h>`, which isn't `-pedantic` clean); the implementation is still compiled as C by the existing test suite.
  - [x] Test coverage for the str8 macros (`STR`/`STR8_ARG`/`STR8_FMT`) and string manipulation (`str8_eq`/`cmp`/`slice`/`trim`, `c_str`, `view_from_str8`/`view_from_bytes`) — covered in `tests/test_strings.c`. (`cstr8` no longer exists; replaced by `str8_view` in v0.0.5.)
  - [ ] Test coverage for `BIT()`/`BIT8/16/32/64()` — the one remaining untested macro group; everything else now has coverage across `tests/test_arenas.c` and `tests/test_strings.c`.
  - [x] Add use-sites for all three `arena_push_array*` macros to a test TU. Macro variants only type-check at expansion, so a typo (e.g. a dropped comma) in `_zero`/`_nozero` compiles clean until first use — a compile-time exercise catches it at the source.
  - [ ] Keep an eye on `ArenaFlags` width (`u8`, room for 4 more flags) — already a known todo in the header; don't let flag #5 become an afterthought.
  - [x] ~~add guards against windows version for ring buffers (`_WIN32` && `NTDDI_VERSION >= NTDDI_WIN10_RS4`)~~ — handled at *runtime* instead: the `GetProcAddress` probe returns `false` on pre-1803 Windows (more precise than a version number, and degrades gracefully). The `MEM_*_PLACEHOLDER` constants are `#ifndef`-supplied so the header still compiles against an older SDK. A hard compile-time `NTDDI` opt-out (to drop the feature entirely on old *targets*) remains optional and unneeded for now.
  - [x] `ring_buffer_read`/`write` guard `NULL rb` for parity with `ring_buffer_peek` — both now check `!rb || !rb->base`.
  - [ ] consider an opt-in overwrite-oldest write mode — `ring_buffer_write` currently rejects when full; a lossy/overwrite policy is handy for telemetry-style streams that prefer freshest data over backpressure.
  - [x] **make the ring buffer safe for cross-thread SPSC use** — `read`/`write` are now published with acquire/release atomics (producer publishes `write` with release after the data copy; consumer loads it with acquire before reading, then publishes `read` with release after consuming; producer loads `read` with acquire before overwriting). Shipped in 0.0.13, covered by the `spsc_stress` case in `tests/test_ring.c`. TSan validation of the ordering itself is still outstanding — blocked on the POSIX port (see `docs/posix-port.md`), since TSan needs a Linux build to run.
  - [ ] (optional) decouple the write side from the read cursor to allow multiple independent readers — move cursor ownership out of the buffer so each reader keeps its own `read`, turning the SPSC FIFO into an SPMC broadcast ring. Consequence: the buffer no longer knows what is "unread", so the write path must change from *reject-when-full* to *overwrite-oldest* (the opt-in overwrite item above becomes mandatory here), and each reader detects it was lapped by comparing its cursor against `write - size`. Only worth it if the two-sink (UDP/TCP) fan-out needs a single shared source rather than one ring per sink — see that tradeoff before committing to it.
